Quando você começa a escrever seus próprios códigos, é natural fazer ajustes, melhorias ou até mesmo desfazer alterações que não deram certo. No início, isso pode parecer simples: salvar várias cópias de um arquivo, criar pastas com nomes como `projeto-final`, `projeto-final-v2`, `versao-ajustada-ok`, e por aí vai.

Mas esse tipo de organização rapidamente se torna **confusa, ineficiente e insegura**, especialmente quando se trabalha em equipe, ou quando seu projeto começa a crescer.

É nesse ponto que entra o conceito de **versionamento de código**.

## Versionamento é um histórico inteligente do seu projeto

O versionamento de código é uma prática que permite **registrar e acompanhar todas as alterações feitas em um projeto ao longo do tempo**, com a capacidade de:

- Saber **quem** fez cada modificação
- Entender **o que foi mudado**
- Comparar versões anteriores
- **Voltar no tempo** caso algo dê errado
- Trabalhar em equipe sem sobrescrever o trabalho dos outros

É como ter um **controle remoto do tempo** para seu código: você pode pausar, voltar, avançar, criar linhas paralelas (ramificações), mesclar mudanças, rever o histórico e colaborar com segurança.

## Versionamento ≠ backup

Embora também proteja seu trabalho, o versionamento é **muito mais que um backup**. Um backup apenas salva o estado atual do projeto. O versionamento **entende as mudanças**, registra **o contexto**, permite **experimentar ideias** sem perder nada e dá suporte à colaboração entre várias pessoas.

Ele também é integrado a práticas modernas de desenvolvimento, como integração contínua (CI), deploy automático, revisão de código (pull requests), e muito mais.

## Git: a ferramenta mais usada para versionamento

Na prática, quando falamos de versionamento, estamos falando do **Git** — a ferramenta mais amplamente utilizada no mundo para controle de versão. Criado por Linus Torvalds (o mesmo criador do Linux), o Git é:

- Gratuito e open source
- Extremamente rápido e eficiente
- Baseado em terminal (mas com interfaces gráficas disponíveis)
- Usado por praticamente todas as empresas e projetos modernos

Com o Git, você pode:

- Iniciar o controle de versão de um projeto (`git init`)
- Salvar versões (chamadas *commits*) conforme for desenvolvendo
- Criar e gerenciar ramificações (*branches*) para novas funcionalidades
- Mesclar mudanças de diferentes fontes
- Compartilhar seu projeto com outros usando plataformas como o **GitHub**

## GitHub: o lar dos seus projetos na nuvem

Git e GitHub andam quase sempre juntos. Enquanto o Git é a ferramenta local (que roda no seu computador), o **GitHub** é um serviço online que permite:

- Armazenar seus repositórios na nuvem
- Compartilhar projetos publicamente ou de forma privada
- Trabalhar de forma colaborativa com outros devs
- Documentar seu projeto com READMEs
- Criar histórico, acompanhar *issues*, fazer *pull requests*, revisar código e mais

Veremos o GitHub mais adiante em sua própria seção, mas é importante já entender que ele funciona como um **hub de colaboração**, onde o Git local se conecta com o mundo externo.
