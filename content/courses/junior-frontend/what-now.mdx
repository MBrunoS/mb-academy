Se você chegou até aqui, parabéns! Você deixou de ser alguém que só escrevia TypeScript em um terminal e se tornou alguém que **constrói interfaces web reais**. Ao longo deste curso, você aprendeu a estruturar páginas com HTML semântico e CSS, fez seu TypeScript conversar com o navegador através do DOM, aprendeu React do zero até Context, consumiu APIs de verdade, lidou com autenticação, escreveu testes automatizados — e, ao final, construiu e publicou um **Dashboard de Finanças** completo, com uma URL real que qualquer pessoa no mundo pode acessar.

Isso não é um exercício de sala de aula. É o mesmo tipo de trabalho que um desenvolvedor júnior front-end faz no primeiro dia de um emprego real.

## O que mudou desde o Starter

No Starter, seu código rodava só para você, no seu terminal. Agora ele roda no navegador de qualquer pessoa, reage a cliques e digitação, busca dados de servidores que você não controla, e continua funcionando mesmo quando a rede falha ou o usuário faz algo inesperado. Esse salto — de "programa que funciona" para "interface que resiste ao mundo real" — é exatamente o que separa quem só aprendeu sintaxe de quem está pronto para o mercado.

## Seu Dashboard de Finanças é um artefato de verdade

Diferente de um exercício que você descarta depois de terminar, o dashboard que você construiu no Capítulo 6 é algo que **continua existindo**: está no seu GitHub, está publicado com uma URL real, e pode entrar no seu portfólio hoje mesmo. Se você seguiu o módulo de Preparação para Entrevistas, já sabe como descrevê-lo de um jeito que destaca as decisões técnicas por trás dele — não "fiz um dashboard", mas "construí uma interface React com TypeScript, consumindo uma API pública, com testes automatizados e deploy em produção".

<Callout type="tip">
  Antes de seguir em frente, considere evoluir o dashboard com um desafio extra: persistência dos gastos entre sessões (`localStorage` ou uma API própria), edição e remoção de gastos, gráficos simples do total por categoria, ou um modo escuro. Cada um desses desafios usa exatamente o que você já aprendeu — só em uma combinação nova.
</Callout>

## Para onde ir agora

Você concluiu o Júnior Front-end. Segundo a trilha da Forja Academy, os próximos passos possíveis são:

### ➤ Pleno Front-end (o caminho principal)

É a continuação direta desta trilha: TypeScript avançado, JavaScript aprofundado (closures, event loop, geradores), Git com branching e convenções, algoritmos e estruturas de dados, Docker, e o salto de React puro para **Next.js** — construindo o mesmo dashboard em uma versão mais sofisticada, com autenticação completa, banco de dados e um design system próprio.

### ➤ Júnior Back-end (opcional, mas recomendado)

Você não precisa saber back-end para avançar no Front-end — as trilhas são paralelas e independentes. Mas entender o outro lado do "contrato de API" que você consumiu neste curso (o que acontece quando um servidor recebe uma requisição, valida dados e fala com um banco de dados) torna você um front-end mais completo, e mais afiado nas entrevistas técnicas. O curso ensina NestJS e PostgreSQL, evoluindo o mesmo domínio de finanças pessoais para uma API REST própria.

## IA como Ferramenta, Não como Muleta

O Capítulo complementar de IA no Desenvolvimento Júnior te mostrou como usar IA para entender erros de CSS e React sem terceirizar o entendimento. Mantenha esse hábito conforme os projetos ficam maiores: peça explicações antes de soluções prontas, e nunca cole no seu código uma linha que você não consegue justificar se alguém perguntar "por que você fez assim?".

## Continue Praticando, Continue Criando

- **Refaça uma parte do dashboard sem olhar o material** — é o teste mais honesto de quanto você realmente absorveu.
- **Explore um framework CSS na prática** (Tailwind, já que é o que o próprio site da Forja Academy usa) em um projeto pequeno.
- **Contribua com um projeto open-source front-end** no GitHub — corrigir um bug de CSS ou melhorar a acessibilidade de um componente são ótimas primeiras contribuições.
- **Comece (ou continue) sua preparação para entrevistas**: com um projeto publicado e uma base sólida em React, você já tem o que precisa para começar a se candidatar a vagas júnior.

## Por fim, lembre-se…

Front-end tem fama de "fácil" justamente por ser visual — mas você sabe, porque viveu, que a dificuldade real está em fazer uma interface reagir com confiança a um mundo imprevisível: dados que demoram, usuários que clicam nas coisas erradas, redes que falham. Você já sabe fazer isso.

Nos vemos na próxima etapa da sua jornada.
